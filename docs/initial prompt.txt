Project name: Sthapana — a data & reporting system for the Establishment
Branch of my University. Project folder: D:\Sthapana\

I'm building this for: Faculty and Staff data, office file records
(notices & circulars), tasks/reminders, and meeting notes/records. I am
a non-programmer.

My PC: 16 GB RAM, i5, Windows. Dev tools: PowerShell + VS Code.

Tech stack: Python, Django + Django REST Framework, Django Templates
with local Bootstrap + Alpine.js for now, Git for version control,
SQLite (with a real, tested backup system) with a possible future move
to PostgreSQL, a custom Django user model, custom exceptions, rotating
logging, and environment-variable-based secrets — all built as the
foundation, not added later. Settings split into base/development/
production from day one.

All templates share one common layout at the templates root; static and
media folders are handled at the project root. Each feature lives in its
own Django app.

Early-gain requirements (important — not the default "admin-only" MVP
approach):
- Login/Logout/Registration pages must be interactive, custom-styled
  pages (not just the Django admin login) — built as part of the
  foundation phase.
- A dashboard shell (with the common layout and placeholder summary
  cards) is also built in the foundation phase.
- Faculty/Staff data (Phase 1) must be modeled as Core fields (stable,
  unlikely to change) + Extension tables (grouped optional fields), so
  new fields can be added later with minimal risk of breaking existing
  screens or reports.
- Faculty/Staff data entry must support BOTH a web form and an Excel
  (.xlsx) import, from Phase 1 onward, sharing the same validation logic
  so data quality is consistent regardless of entry channel.
- The backup system's infrastructure (scheduled copy + pruning script)
  is built in the foundation phase, so it's protecting data from the
  very first real record — its restore process is tested for real once
  Phase 1 has actual data.

Later phases (not now) will add: a Telegram bot (deterministic commands
first), an Intent Router (rule-based + fuzzy matching) to handle
human-like commands, an AI/LLM layer, and Tools apps for Filesystem,
Excel, Word, PDF, and Google (Gmail, Drive, Calendar, Sheets). The
system must always work deterministically first — the AI layer is a
convenience layered on top later, never a replacement.
